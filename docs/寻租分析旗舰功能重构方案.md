# 寻租分析旗舰功能重构方案

## 1. 重构目标

寻租分析应从当前“风险分析列表 + 详情页”的普通模块，升级为平台第一主功能。重构后的定位是：围绕制度文本、冲突线索、风险规则、LLM 推理和 RAG 证据检索，形成一个可解释、可复核、可报告的寻租风险分析工作台。

重构目标包括：

- UI 中突出寻租分析入口，使其成为登录后的主工作区和制度详情页的核心操作。
- 功能上加强风险识别、证据定位、原因解释、整改建议、复核流转和报告沉淀。
- 技术上绑定 LLM 与 RAG，将模型分析从“可选辅助”升级为“增强分析层”，同时保留本地规则兜底。
- 数据上沉淀风险指标、命中规则、引用证据、模型输出、人工复核和整改闭环。

## 2. 产品定位

寻租分析中心是平台主体验，其他模块围绕它提供支撑：

| 模块 | 对寻租分析的支撑 |
| --- | --- |
| 制度管理 | 提供制度元数据、正文、版本和分析入口 |
| 冲突检测 | 提供重复、适用范围差异、主体差异等制度缺陷线索 |
| AI 服务 | 提供 LLM 分析、提示词模板、调用记录和模型配置 |
| RAG 知识库 | 提供制度条款、监管依据、历史案例和整改模板证据 |
| 看板报告 | 展示分析覆盖率、风险等级、风险趋势和整改成效 |
| 系统审计 | 记录分析、复核、参数变更和模型调用过程 |

## 3. UI 重构

### 3.1 导航与信息架构

- 将菜单 `风险分析` 改为 `寻租分析中心`，在侧边栏中置于 `制度管理` 之后、`冲突检测` 之前或作为首个业务菜单。
- 工作台首页增加“寻租分析总览”区域，包括待分析制度、严重风险、待复核风险、LLM/RAG 配置状态。
- 制度详情页将“发起寻租分析”作为主按钮，弱化普通编辑类操作。
- 新增 `寻租分析中心` 首页，聚合待分析制度、最新分析结果、高风险清单、整改建议和模型状态。

### 3.2 页面改造

| 页面 | 改造方向 |
| --- | --- |
| `/dashboard` | 增加旗舰分析总览、风险热区、模型状态、待办入口 |
| `/regulations/:id` | 增加主 CTA：发起寻租分析、查看最近分析、查看证据引用 |
| `/risks` | 改为寻租分析中心，支持按风险等级、指标、部门、复核状态、是否 LLM 增强筛选 |
| `/risks/:id` | 改为分析工作台详情，展示风险结论、证据、模型理由、RAG 引用、人工复核 |
| `/ai/records` | 增加从分析详情反查模型调用记录的入口 |
| `/system/configs` | 增加 LLM 与 RAG 配置分组和连通性检测 |

### 3.3 详情页展示结构

寻租分析详情页建议分为五个区域：

- 风险结论：等级、分数、摘要、是否 LLM 增强、是否 RAG 命中。
- 风险项：指标编码、风险标题、关联条款、判定原因、整改建议。
- 证据链：制度原文片段、冲突线索、RAG 检索引用、历史相似案例。
- 模型解释：LLM 原始摘要、结构化 JSON、提示词版本、模型名称。
- 人工复核：确认、调整、忽略、备注、整改责任和状态。

## 4. 功能加强

### 4.1 风险指标体系

将当前硬编码规则抽象为可配置指标：

| 指标 | 当前能力 | 增强方向 |
| --- | --- | --- |
| 自由裁量权 | 关键词命中 | 识别模糊授权、例外审批、兜底条款 |
| 审批集中度 | 审批关键词 | 识别单点审批、缺少复核、权责不分 |
| 流程透明度 | 缺失公开、公示、时限、标准 | 结合流程语义判断是否缺少可执行标准 |
| 监督约束 | 缺失监督、复核、问责 | 判断监督主体、频次、责任是否明确 |
| 利益关联 | 资金、补贴、资格、资源 | 识别利益输送、资格裁量、资源配置风险 |
| 处罚弹性 | 处罚、减免、从轻、从重 | 识别同案不同罚和处罚幅度过宽 |

### 4.2 分析流程

建议采用四层分析：

1. 规则兜底层：本地规则先产出基础风险项，保障无 LLM 环境可用。
2. 冲突线索层：把冲突检测结果作为风险分析上下文，例如适用范围冲突可增强流程透明度风险。
3. RAG 证据层：检索制度库、监管依据、历史案例、整改模板，补充可引用证据。
4. LLM 推理层：基于制度正文、规则命中、冲突线索和 RAG 证据生成结构化分析结果。

### 4.3 结果结构

风险分析结果需要增加这些字段：

- `analysisMode`：`RULE_ONLY`、`LLM_ENHANCED`、`RAG_ENHANCED`。
- `evidenceRefs`：引用证据列表。
- `promptVersion`：提示词版本。
- `modelName`：模型名称。
- `confidence`：模型置信度或系统综合置信度。
- `sourceTrace`：风险项来源，包括规则、LLM、RAG、人工调整。
- `rectificationStatus`：整改状态。

## 5. LLM 绑定

### 5.1 LLM 在寻租分析中的职责

LLM 不只做文本润色，应承担以下增强职责：

- 输出制度摘要和分析范围。
- 根据风险指标识别隐性风险。
- 对每个风险项给出判定原因。
- 对关联条款进行自然语言解释。
- 结合证据输出整改建议。
- 输出结构化 JSON，供后端持久化和前端展示。

### 5.2 提示词结构

LLM 输入建议包含：

- 制度标题、部门、适用范围、状态。
- 制度正文或分段条款。
- 本地规则命中的风险项。
- 冲突检测线索。
- RAG 检索到的监管依据、历史案例、整改模板。
- 输出 JSON Schema 要求。

### 5.3 降级策略

- LLM 未配置：使用规则兜底，分析模式为 `RULE_ONLY`。
- LLM 调用失败：记录失败原因，保留规则结果。
- LLM 返回格式错误：保存原文，尝试 JSON 提取；失败则降级规则结果。
- LLM 与规则冲突：同时展示来源，交给人工复核。

## 6. RAG 绑定

### 6.1 RAG 知识来源

RAG 不应只检索当前制度，应建设面向寻租分析的证据库：

| 知识来源 | 用途 |
| --- | --- |
| 当前制度正文 | 定位风险条款 |
| 历史制度库 | 查找相似制度和相似风险 |
| 外部监管政策 | 提供上位依据和监管要求 |
| 历史分析结果 | 复用已确认风险和复核意见 |
| 整改建议库 | 推荐整改表达和治理措施 |
| 冲突检测结果 | 作为制度缺陷证据 |

### 6.2 RAG 流程

1. 制度入库后按条款切分。
2. 为条款、标题、部门、适用范围生成向量。
3. 发起寻租分析时，以制度正文、风险指标和规则命中词构造查询。
4. 检索相似条款、监管依据、历史案例和整改模板。
5. 将 Top-K 结果作为证据传给 LLM。
6. LLM 输出风险项时必须引用证据编号。
7. 前端展示证据来源、片段和相似度。

### 6.3 技术选型建议

MVP 增强阶段可先采用轻量方案：

- MySQL 存储知识片段、引用关系和元数据。
- 向量库可预留接口，初期可使用外部向量服务或 PostgreSQL/pgvector 作为后续替换目标。
- 后端新增 `rag` 包，封装切分、索引、检索、引用组装。
- 系统参数增加 embedding 模型、检索 Top-K、相似度阈值、知识源开关。

## 9. 实施路线

### 阶段 A：UI 突出

- 菜单改名为 `寻租分析中心`。
- 工作台增加旗舰分析概览。
- 制度详情页强化发起分析按钮。
- 风险详情页增加分析模式、规则来源和人工复核信息。

### 阶段 B：功能加强

- 抽取本地规则为 `RiskRuleEngine`。
- 增加风险项来源、关联条款、证据列表和复核状态。
- 支持风险项级复核和整改状态。
- 报告预览优先展示寻租分析结论。

### 阶段 C：LLM 深度绑定

- 完善 OpenAI-compatible 客户端。
- 增加提示词版本和结构化输出校验。
- 让 LLM 输入包含规则命中和冲突线索。
- 分析详情页展示模型摘要、模型理由和调用记录。

### 阶段 D：RAG 接入

- 建立知识切片和索引任务。
- 支持制度库、监管政策、历史案例检索。
- LLM 输出必须绑定 RAG 证据编号。
- 前端展示证据片段、来源和相似度。

### 阶段 E：质量闭环

- 用人工复核结果回流优化规则和提示词。
- 增加分析质量指标：命中率、确认率、调整率、误报率。
- 增加模型配置连通性测试和 RAG 检索质量测试。

## 10. 验收标准

- 用户登录后能明显看到 `寻租联合分析`，并能从工作台、菜单和旧问答路径重定向进入。
- 未配置 LLM 时，系统仍能生成风险分析结果，且标记为规则兜底。
- 配置 LLM 后，分析结果包含摘要、风险等级、风险项、判定原因和整改建议。
- 配置 RAG 后，风险项至少能展示引用证据、来源和相似度。
- 风险项支持人工确认、调整、忽略和备注。
- 报告预览以寻租分析结论为核心，展示风险项、证据和整改建议。
- 所有 LLM 调用、RAG 检索和人工复核均有记录可追踪。

## 11. 真实样本优化补充

围绕郴州烟花爆竹零售店燃爆事件，寻租分析功能需要避免只输出泛化风险，应采用“真实制度正文 + 本地规则线索 + RAG 证据 + LLM 细化推理”的组合。

优化要求：

- 制度正文不只保留短摘要，应包含来源 URL、发布主体、制度定位、条文要点、可分析字段和具体寻租场景。
- 本地规则先识别具体线索，例如许可证到期与春节备货窗口重叠、发证机关其他材料兜底、停止办理行政许可衔接不明、库存回购和迁址重申办利益分配。
- RAG 检索应自动补齐未索引制度，过滤已删除制度片段，并提高真实制度样本的证据召回数量。
- LLM 输入必须包含本地规则线索和 RAG 证据，提示词要求风险项写清楚权力节点、经营者处境、可交换利益、机会成本差、证据引用和可执行整改动作。
- LLM 输出过少或过泛时，系统应合并本地规则线索，避免真实模型调用成功但结果质量低于规则兜底。
- OpenAI-compatible 地址应兼容常见 `/v1/chat/completions`、`/chat/completions`、Gemini `/openai/chat/completions` 等路径，避免模型配置真实可用但因路径拼接错误降级。

## 12. 案例扩展分析补充

原 `制度问答` 入口升级为 `案例扩展分析`：用户输入真实案例事实后，系统围绕案例自动检索已导入制度，并可抓取用户提供的官方公开链接正文片段，输出相关法律公文、组织责任链、具体寻租风险点和待手动导入材料清单。

实现边界：

- 后端接口为 `POST /api/ai/cases/analyze`，原 `/api/ai/regulations/{id}/chat` 保留兼容。
- 已导入制度通过 RAG 跨制度召回，不再局限于单份制度正文。
- 自动抓取限定为用户提供的 `http/https` 公开链接；PDF 暂不解析正文，会提示下载后导入文本。
- 没有链接或抓取不足时，系统必须列出应导入的法律公文、地方政策、事故调查材料、行政许可清单和组织架构职责。
- 以郴州烟花爆竹零售店燃爆事件为默认案例，内置分析重点包括许可证有效期与春节旺季错配、布点和现场核查集中、禁燃区边界裁量、停止办理许可衔接、库存回购和迁址重新申办。

## 13. 规章集隔离补充

制度库需要支持多个相互独立的规章体系并存，避免分析另一个行业、地区或事项时必须删除现有制度。`规章集` 作为制度、RAG 召回、案例分析和冲突检测的上层范围，用于区分不同监管体系。

实现要求：

- 新增 `regulation_set` 数据实体，包含规章集名称、编码、说明、是否启用、是否默认和制度数量。
- `regulation` 增加 `regulation_set_id`，制度编号唯一性从全库唯一调整为同一规章集内唯一，允许不同规章集复用相同制度编号。
- 现有制度迁移到默认规章集 `烟花爆竹监管制度集`，保持历史数据和原有分析入口可用。
- 制度管理、制度详情、案例扩展分析、冲突检测创建任务均需要显示规章集选择器，并默认选中默认规章集。
- 案例扩展分析的 RAG 召回应按所选规章集过滤，避免跨行业、跨地区制度混入证据链。
- 冲突检测任务应限制在同一规章集内创建；后端需要校验所选制度属于同一规章集。
- 用户新建独立监管体系时，只需新建规章集并导入该集合下的制度，不影响原有烟花爆竹监管样本。

## 14. 案例-规章集联合分析补充

最终分析入口应把两个方向合流：一条线从案例事实出发，抽取权力节点、利益节点、时间窗口、机会成本差和异常激励；另一条线从用户指定的主规章集 A 出发，先推理 A 内部的制度内生风险，再召回 A 之外的外部约束证据 B。

实现边界：

- 保留 `/api/ai/cases/analyze` 作为统一入口，新增 `jointAnalysis` 和 `externalDiscovery` 参数；默认开启联合分析。
- 规章集 A 是主分析对象，外部制度 B 只作为本次分析的外部约束证据集，不直接物理合并进 A。
- 联合分析最多执行两轮有限迭代：第一轮抽取案例触发风险和 A 内部风险，第二轮召回 A 之外的上位法、程序法、资金规则、监督问责、组织职责等约束证据。
- 输出结构新增 `internalRisks`、`caseRegulationMappings`、`externalConstraints`、`closureGaps` 和 `iterationTraces`。
- 报告必须区分三类结论：案例触发型风险、制度内生型风险、制度闭环缺口。
- 停止条件包括：达到两轮迭代上限、外部证据不足、候选制度只提供事后问责而不能补足事前控制、需要人工确认适用性。
- 前端 `案例扩展分析` 页面升级为 `案例-规章集联合分析`，默认展示主规章集 A、A 内部风险图谱、案例-A 映射、外部约束证据 B、闭环缺口和有限迭代轨迹。

## 15. 联网发现与自动导入补充

为降低用户手动搜集制度材料的成本，联合分析入口新增“联网发现 -> 候选来源 -> 确认导入 -> RAG 召回”的闭环。

实现边界：

- 新增 `POST /api/ai/web-sources/discover`，根据案例标题、案例事实和主规章集 A 生成检索词，优先从 `gov.cn`、人大、主管部门官网等可核验来源发现候选公文。
- 新增 `POST /api/ai/web-sources/import`，用户勾选候选来源后，后端重新抓取网页正文，导入目标规章集并立即建立知识索引。
- 默认导入目标为 `联网发现外部约束集`，使新材料作为 A 之外的外部约束 B 被联合分析召回；用户也可指定其他规章集。
- 自动导入只处理可抓取 HTML 正文；PDF 或抓取失败材料保留为候选来源或手动导入建议，避免生成无正文证据。
- 抓取结果必须保留来源 URL、域名、抓取状态和说明，导入正文首部写入来源信息，便于事后审计。
- 对部分政府网站证书链不完整的情况，后端在默认 HTTPS 校验失败后启用公开网页抓取兜底，以保证真实政府来源能被读取。
- 前端主入口改为 `寻租联合分析`，路径为 `/rent-seeking-analysis`；工作台增加直达按钮，原 `/ai/regulation-qa` 保留重定向兼容。
