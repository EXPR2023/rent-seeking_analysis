# 规章寻租行为分析平台概述

## 1. 项目背景

企业内部规章、业务制度以及外部监管政策在组织治理、合规管理、业务审批、资源配置和公共服务中具有基础性作用。当文本条款存在模糊空间、冲突漏洞、权力过度集中、自由裁量边界不清或审批流程不透明时，可能形成寻租行为的制度土壤。

规章寻租行为分析平台以寻租风险分析为旗舰功能，通过制度文本管理、冲突检测、规则化风险识别、AI 语义增强和可视化报告能力，对内部制度和外部导入监管政策中的潜在寻租风险进行系统化分析，帮助管理者发现制度缺陷、优化流程设计、提升治理透明度和合规水平。

## 2. 建设目标

平台建设目标包括：

- 建立统一的规章制度管理体系，实现制度文件的分类、版本、状态和生命周期管理。
- 对制度文本中的冲突、重复、模糊、授权不清等问题进行自动化检测。
- 构建旗舰寻租风险分析能力，分析制度条款、流程节点和权限配置中的自由裁量、审批集中、透明度不足和监督缺位等风险。
- 引入 AI 分析服务，增强制度解读、风险归因、整改建议和报告生成；未配置 AI 时仍通过本地规则保障分析闭环可运行。
- 通过图表、指标和报告呈现制度风险分布、趋势变化和重点问题。
- 建立用户、角色、权限和审计能力，保障系统安全、可追溯和可扩展。

## 3. 技术栈规划

### 3.1 后端主栈

- Spring Boot：作为核心业务服务开发框架，承载用户管理、制度管理、风险分析、报告管理等业务能力。
- Spring Security：负责认证、授权、权限控制、接口安全和安全上下文管理。
- Spring Cloud Gateway：作为系统统一网关，处理路由转发、鉴权入口、限流、日志追踪和跨服务访问控制。
- Spring AI：对接大模型能力，用于制度文本理解、冲突说明、风险摘要、整改建议和智能问答。
- MySQL：存储用户、权限、制度元数据、分析结果、风险指标、报告记录等结构化数据。
- Redis：用于缓存、会话、验证码、热点数据、异步任务状态和限流辅助。

### 3.2 前端技术栈

- Vue 3：构建平台前端应用，采用组件化方式组织业务界面。
- Element Plus：提供表单、表格、弹窗、菜单、权限配置、上传等基础 UI 能力。
- ECharts：实现风险趋势、制度关系、冲突分布、风险等级、部门对比等可视化图表。

## 4. 总体架构

平台可采用前后端分离架构，后端按业务领域划分模块，前端围绕业务工作台组织页面能力。

建议整体架构如下：

- 前端展示层：提供用户操作界面、制度维护、风险分析、图表展示和报告查看能力。
- 网关接入层：统一处理请求入口、身份校验、路由转发、访问控制、限流和日志。
- 业务服务层：承载用户权限、制度管理、冲突检测、风险分析、AI 分析、报告生成等核心业务逻辑。
- AI 能力层：通过 Spring AI 对接大语言模型、向量检索或知识库能力，提供智能分析服务。
- 数据存储层：使用 MySQL 存储核心业务数据，Redis 支撑缓存与高频状态数据。
- 基础设施层：提供日志、审计、配置、任务调度、异常处理、监控预警等支撑能力。

## 5. 功能模块概述

### 5.1 用户与权限管理模块

用于管理平台用户、组织、角色、权限和访问控制。

主要功能包括：

- 用户注册、登录、登出和密码管理。
- 用户状态管理，包括启用、禁用、锁定和重置密码。
- 角色管理，包括系统管理员、制度管理员、分析人员、审计人员、普通查看用户等。
- 菜单权限、按钮权限和接口权限配置。
- 组织或部门维度的数据权限控制。
- 登录日志、操作日志和权限变更记录。

### 5.2 规章制度管理模块

用于规章制度文件的统一归集、结构化管理和版本维护。

主要功能包括：

- 制度文件上传、录入、编辑、删除和归档。
- 支持制度标题、编号、发布部门、生效日期、失效日期、适用范围、制度类型等元数据管理。
- 支持制度正文、章节、条款、附件等结构化存储。
- 制度版本管理，记录修订历史和变更说明。
- 制度状态管理，包括草稿、待审核、已发布、已废止等。
- 制度全文检索和条件筛选。

### 5.3 制度冲突检测模块

用于识别不同制度之间或同一制度内部的条款冲突、重复和不一致问题。

主要功能包括：

- 条款相似度检测，发现重复或高度相似内容。
- 制度适用范围冲突检测。
- 权责主体不一致检测。
- 生效时间、审批流程、处罚标准等关键规则冲突检测。
- 冲突问题分级，包括严重冲突、一般冲突、提示性冲突。
- 冲突检测结果展示、人工确认和处理状态跟踪。

### 5.4 寻租风险分析模块

平台旗舰功能，用于识别制度设计中可能诱发寻租行为的风险点，并沉淀可复核、可整改、可报告的结构化分析结果。该模块应作为制度详情、看板统计和报告预览的核心数据来源。

主要功能包括：

- 风险指标体系配置，包括自由裁量权、审批集中度、流程透明度、监督约束、利益关联、处罚弹性等。
- 条款级风险识别，对制度文本中的模糊授权、例外条款、审批空间、监管缺失进行标记。
- 流程级风险识别，分析审批链路、关键节点和权力集中情况。
- 风险评分与等级划分，形成低、中、高、严重等风险等级。
- 风险原因分析，说明风险来源和影响范围。
- 整改建议管理，支持记录建议、责任部门、处理进度和复核结果。
- 本地规则兜底，在未配置 LLM 时仍可输出风险等级、风险项和整改建议。
- LLM 语义增强，在配置模型后提升摘要、归因、条款解释和整改建议的细致度。

### 5.5 AI 分析服务模块

用于通过大模型能力提升制度分析的自动化和解释性。

主要功能包括：

- 制度文本摘要，自动生成制度要点、适用范围和核心要求。
- 条款解读，对复杂制度内容进行自然语言解释。
- 冲突原因说明，辅助分析冲突条款之间的差异和影响。
- 寻租风险归因，解释风险形成机制和可能后果。
- 整改建议生成，辅助提出制度优化、流程调整和监督增强建议。
- AI 问答服务，支持基于制度库的自然语言查询。
- 提示词模板管理，规范不同分析场景下的 AI 输入输出格式。

### 5.6 可视化与报告模块

用于展示制度风险整体情况，并输出分析报告。

主要功能包括：

- 风险总览看板，展示制度数量、风险数量、冲突数量、整改完成率等核心指标。
- 风险等级分布图、部门风险排行、制度类型风险分布、风险趋势图。
- 制度冲突关系图，展示制度之间的冲突或关联关系。
- 单项制度分析报告，展示制度摘要、冲突问题、风险点和整改建议。
- 综合分析报告，支持按部门、时间、制度类型、风险等级生成。
- 报告导出能力，支持 Word、PDF 或 Excel 等格式的后续扩展。

### 5.7 系统基础设施模块

用于保障平台稳定运行、安全访问和后续扩展。

主要功能包括：

- 统一异常处理和错误响应。
- 系统参数配置和字典管理。
- 操作审计与日志追踪。
- 定时任务管理，例如定期风险扫描、报告生成、缓存清理。
- 文件存储管理，用于制度原文、附件和报告文件。
- 接口文档、健康检查、服务监控和告警扩展。
- 数据备份、恢复和安全策略配置。

## 6. 核心业务流程

### 6.1 制度入库流程

1. 制度管理员上传或录入制度文件。
2. 系统解析制度元数据和正文内容。
3. 管理员补充制度分类、适用范围、发布部门等信息。
4. 制度进入审核或发布流程。
5. 发布后的制度进入冲突检测和风险分析范围。

### 6.2 冲突检测流程

1. 用户选择待检测制度或制度集合。
2. 系统提取条款、主体、时间、流程、权限等关键要素。
3. 系统执行相似度、规则冲突和语义冲突检测。
4. 生成冲突结果和冲突等级。
5. 用户进行人工确认、标记处理意见并跟踪整改状态。

### 6.3 寻租风险分析流程

1. 用户从制度详情或风险分析入口发起寻租分析。
2. 系统读取制度元数据和正文，优先基于风险指标体系执行本地规则扫描。
3. 若已配置 LLM，AI 服务在规则兜底基础上增强模糊授权、审批空间、监督缺失等风险点的语义识别和归因说明。
4. 系统计算或接收风险评分并生成风险等级。
5. 平台输出风险原因、影响范围、关联条款和整改建议。
6. 责任部门处理风险问题，审计或管理人员进行复核。

### 6.4 报告生成流程

1. 用户选择报告范围，例如单项制度、部门、时间区间或制度类型。
2. 系统汇总制度信息、冲突结果、风险分析结果和整改状态。
3. AI 服务辅助生成摘要、结论和建议。
4. 用户预览、编辑并导出报告。

## 7. 数据对象初步规划

核心数据对象包括：

- 用户：账号、姓名、手机号、邮箱、状态、所属组织。
- 角色：角色编码、角色名称、权限范围、数据权限。
- 权限：菜单权限、按钮权限、接口权限。
- 组织：组织名称、上级组织、组织类型。
- 制度：标题、编号、类型、发布部门、状态、生效日期、版本号。
- 制度条款：章节编号、条款编号、条款内容、关键词、结构化要素。
- 冲突记录：冲突制度、冲突条款、冲突类型、冲突等级、处理状态。
- 风险指标：指标名称、指标权重、评分规则、适用场景。
- 风险结果：风险对象、风险等级、风险评分、风险原因、整改建议。
- AI 分析记录：分析类型、输入内容、输出内容、模型信息、调用时间。
- 报告：报告名称、报告类型、生成范围、生成状态、文件地址。
- 审计日志：操作人、操作类型、操作对象、操作时间、操作结果。

## 8. 安全与权限设计

平台安全设计建议包括：

- 基于 Spring Security 实现统一认证和授权。
- 支持 JWT、Session 或 OAuth2 等认证方案，具体方案可根据部署环境确定。
- 通过角色权限控制用户可访问的菜单、页面和接口。
- 通过数据权限限制用户只能访问授权部门或授权制度范围内的数据。
- 对制度删除、报告导出、权限变更、风险复核等敏感操作记录审计日志。
- 对 AI 分析请求进行权限校验、内容脱敏和调用频率控制。
- 对网关入口进行限流、防刷、跨域控制和统一安全响应处理。

## 9. AI 能力建设思路

AI 分析服务可分阶段建设：

- 第一阶段：围绕旗舰寻租分析，基于提示词模板实现制度摘要、条款解读、风险说明和整改建议生成。
- 第二阶段：建设制度知识库，引入向量检索能力，实现基于制度库的问答和语义检索。
- 第三阶段：结合规则引擎、风险指标体系和模型分析结果，形成可解释的综合风险评分。
- 第四阶段：沉淀人工复核数据，优化风险识别规则和提示词模板，提升分析准确性。

AI 输出应保留人工确认机制。对冲突结论、风险等级和整改建议等关键结果，应支持人工复核、修正和追踪。

## 10. 部署与扩展建议

初期可采用单体后端加网关的方式降低复杂度，待业务增长后再按模块拆分为独立服务。

建议演进路线：

- MVP 阶段：完成用户权限、制度管理、基础冲突检测、旗舰寻租风险分析和看板展示，并保证无 LLM 环境下可演示。
- 增强阶段：接入 Spring AI 或 OpenAI-compatible LLM，完善 AI 解读、风险归因、报告生成和案例扩展分析。
- 平台化阶段：引入服务拆分、任务队列、知识库、监控告警和多租户能力。
- 智能化阶段：形成风险规则库、案例库和持续优化的 AI 分析闭环。

## 11. 初步里程碑

| 阶段 | 建设重点 | 主要成果 |
| --- | --- | --- |
| 第一阶段 | 项目基础能力 | 用户权限、系统基础框架、制度管理 |
| 第二阶段 | 分析能力 | 制度冲突检测、旗舰寻租风险指标体系、风险结果管理 |
| 第三阶段 | AI 能力 | AI 摘要、条款解读、风险归因、整改建议 |
| 第四阶段 | 可视化与报告 | 风险看板、统计图表、报告生成与导出 |
| 第五阶段 | 运维与优化 | 审计日志、监控告警、性能优化、安全加固 |
