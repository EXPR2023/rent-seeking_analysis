# 规章寻租行为分析平台 MVP 原型开发文档

## 1. 文档目的

本文档用于指导规章寻租行为分析平台的最小可行性原型开发。平台既支持企业内部规章制度分析，也支持外部导入监管政策文本的寻租风险分析。寻租风险分析是本项目的旗舰功能，MVP 应优先保证该链路可演示、可解释、可复核：未配置 LLM 时通过本地规则形成稳定结果，配置 LLM 后增强摘要、归因、评分和整改建议。项目采用敏捷开发模型，并遵循“先原型验证、后增量建设”的路径，优先交付可演示、可验证、可反馈的核心闭环，再逐步扩展完整平台能力。

MVP 阶段要求跑通所有规划模块，但不追求每个模块一次性实现完整深度。原型以“寻租分析主链路清晰、全模块有入口、关键数据可流转”为目标，先形成用户与权限管理、规章制度管理、制度冲突检测、寻租风险分析、AI 分析服务、可视化与报告、系统基础设施七个模块的最小可行闭环。

## 2. 开发模式

### 2.1 敏捷开发模型

项目采用短周期迭代方式推进，每个迭代周期建议为 1 至 2 周。

每个迭代包含：

- 需求梳理：明确本轮迭代目标、用户故事和验收标准。
- 原型设计：形成页面草图、交互流程和关键字段。
- 开发实现：完成前后端功能、数据结构和接口联调。
- 测试验证：进行功能测试、接口测试和基本安全验证。
- 评审反馈：邀请业务用户或项目负责人进行演示评审。
- 迭代调整：根据反馈修正需求优先级和后续计划。

### 2.2 先原型后增量

开发路径分为两个阶段：

- 原型阶段：快速搭建可运行原型，验证全部模块是否能够串联运行，包括登录授权、制度录入、冲突检测、风险分析、AI 辅助、看板报告和基础配置。
- 增量阶段：在原型基础上逐步增强算法准确性、权限精细度、报告导出、审计追踪、服务治理和平台化部署能力。

该路径有助于尽早暴露业务理解偏差和技术风险，减少后期返工。

## 3. MVP 建设目标

MVP 原型需要达成以下目标：

- 用户可以登录系统并进入工作台。
- 管理员可以维护基础用户、角色和菜单权限。
- 用户可以维护基础制度信息和制度正文。
- 用户可以对制度执行最小化冲突检测。
- 用户可以对单项制度发起旗舰寻租风险分析。
- 系统可以生成制度摘要、风险点、风险等级、判定原因、关联条款和整改建议。
- 用户可以查看制度风险分析结果。
- 用户可以在看板中查看基础统计图表。
- 用户可以预览单项制度分析报告。
- 管理员可以查看基础操作日志、系统参数和服务状态。

## 4. MVP 范围

### 4.1 MVP 覆盖原则

MVP 原型必须覆盖全部规划模块。每个模块至少提供一个可访问页面、一组可调用接口、一套最小数据结构和一个可演示业务动作。

覆盖原则如下：

- 用户与权限管理模块：跑通登录、用户列表、角色分配和菜单权限展示。
- 规章制度管理模块：跑通制度新增、编辑、查询、详情和正文维护。
- 制度冲突检测模块：跑通制度间相似条款或规则冲突的最小检测流程。
- 寻租风险分析模块：作为旗舰功能，跑通风险指标、风险评分、风险点识别、原因解释、整改建议和结果复核。
- AI 分析服务模块：围绕寻租分析增强制度摘要、风险识别、冲突说明和整改建议生成。
- 可视化与报告模块：跑通风险看板、图表统计和单项报告预览。
- 系统基础设施模块：跑通系统参数、操作日志、健康检查和基础网关入口。

### 4.2 MVP 深度控制

MVP 阶段允许使用简化实现，但所有简化点必须可被后续增量替换。

简化范围如下：

- 权限模型先采用基础 RBAC，不实现复杂组织数据权限。
- 冲突检测先采用关键词、条款相似度和规则字段比对，不实现完整语义推理。
- 风险评分先采用本地规则兜底，配置 LLM 后可采用模型建议分数和结构化风险项，不实现复杂权重配置。
- AI 问答先实现单项制度上下文问答，不建设完整向量知识库。
- 报告先实现页面预览，不强制实现 Word、PDF、Excel 导出。
- 基础设施先实现单体应用内模块化，不强制拆分微服务。
- Spring Cloud Gateway 可在原型中作为独立入口服务或预留网关工程，至少跑通统一路由和健康检查。

## 5. MVP 用户角色

MVP 阶段先保留少量角色，降低权限复杂度。

| 角色 | 说明 | 核心权限 |
| --- | --- | --- |
| 系统管理员 | 管理基础账号和系统配置 | 登录、查看全部数据、维护用户 |
| 制度管理员 | 维护制度信息 | 制度新增、编辑、查看、发起分析 |
| 分析人员 | 查看和复核分析结果 | 查看制度、发起分析、查看报告 |
| 只读用户 | 浏览结果 | 查看制度、查看看板、查看报告 |

MVP 可先通过固定角色或初始化账号实现权限控制，后续再扩展为完整 RBAC 权限体系。

## 6. MVP 核心业务流程

### 6.1 用户与权限流程

1. 管理员登录系统。
2. 进入用户与权限管理页面。
3. 新增或启用一个用户。
4. 为用户分配基础角色。
5. 系统根据角色展示可访问菜单。
6. 用户操作记录写入操作日志。

### 6.2 制度录入流程

1. 用户登录系统。
2. 进入制度管理页面。
3. 新增制度基础信息。
4. 录入制度正文。
5. 保存制度，制度状态默认为“草稿”或“已录入”。
6. 用户可进入制度详情查看完整内容。

### 6.3 制度冲突检测流程

1. 用户进入制度冲突检测页面。
2. 选择一项主制度和一项或多项对比制度。
3. 系统提取制度标题、适用范围、关键条款和关键词。
4. 系统执行相似条款、适用范围和规则字段的简化冲突检测。
5. 前端展示冲突类型、冲突等级、涉及制度和涉及条款。
6. 用户可对冲突结果进行确认、忽略或备注。

### 6.4 寻租风险分析流程

1. 用户在制度详情页点击“发起风险分析”。
2. 后端读取制度正文和制度元数据。
3. 系统先执行本地风险规则，识别自由裁量、审批集中、流程透明度不足、监督约束不足、利益关联和处罚弹性等风险。
4. 若已配置 LLM，系统调用 AI 分析服务增强制度摘要、风险归因、关联条款、风险等级和整改建议。
5. 系统保存制度摘要、风险点、风险等级、风险原因、整改建议和复核状态。
6. 前端展示分析结果。
7. 用户可进行人工确认或备注。

### 6.5 AI 分析服务流程

1. 业务模块向 AI 分析服务提交制度上下文和分析目标。
2. AI 分析服务根据场景选择提示词模板。
3. AI 模型返回结构化分析结果。
4. 系统对返回内容进行格式校验。
5. 系统保存 AI 分析记录，供风险分析、冲突检测和报告模块复用。

### 6.6 看板展示流程

1. 用户进入风险看板。
2. 系统统计制度总数、已分析制度数、冲突数量、风险数量和风险等级分布。
3. 前端通过 ECharts 展示风险等级分布、制度类型分布和冲突状态分布。
4. 用户可点击指标跳转至对应列表。

### 6.7 报告预览流程

1. 用户进入制度分析结果页。
2. 点击“报告预览”。
3. 系统聚合制度信息、冲突结果、AI 摘要、风险点和整改建议。
4. 前端以报告页面形式展示。
5. MVP 阶段先支持页面预览，导出能力后续实现。

### 6.8 系统基础设施流程

1. 管理员进入系统管理页面。
2. 查看系统参数、缓存状态、服务健康状态和操作日志。
3. 管理员维护基础字典或参数配置。
4. 系统记录参数变更日志。
5. 健康检查接口可用于验证后端、网关、数据库和 Redis 状态。

## 8. 技术实现范围

### 8.1 后端原型范围

MVP 后端建议采用单体 Spring Boot 项目实现，内部按模块分包，暂不进行微服务拆分。

建议模块结构：

```text
backend
├── auth
├── user
├── role
├── regulation
├── conflict
├── risk
├── ai
├── dashboard
├── report
├── system
├── audit
└── common
```

主要技术使用：

- Spring Boot：业务接口与核心服务。
- Spring Security：登录认证和基础接口保护。
- Spring Cloud Gateway：提供统一路由入口和服务健康检查入口。
- MySQL：持久化用户、制度、风险结果和报告数据。
- Redis：用于登录状态、热点统计缓存和基础限流计数。
- Spring AI：封装 AI 分析服务调用。

### 8.2 前端原型范围

MVP 前端采用 Vue 3 + Element Plus + ECharts。

建议页面结构：

```text
frontend
├── 登录页
├── 工作台首页
├── 用户与权限
│   ├── 用户列表
│   └── 角色权限
├── 制度管理
│   ├── 制度列表
│   ├── 制度表单
│   └── 制度详情
├── 冲突检测
│   ├── 检测任务
│   └── 冲突结果
├── 风险分析
│   └── 分析结果详情
├── AI 分析服务
│   ├── 分析记录
│   └── 案例扩展分析
├── 可视化看板
├── 报告预览
└── 系统管理
    ├── 系统参数
    ├── 字典管理
    ├── 操作日志
    └── 健康检查
```

### 8.3 数据库范围

MVP 阶段建议先设计以下核心表：

- sys_user：用户表。
- sys_role：角色表。
- sys_user_role：用户角色关联表。
- sys_menu：菜单权限表。
- regulation：制度主表。
- regulation_content：制度正文表。
- conflict_detection_task：冲突检测任务表。
- conflict_item：冲突明细表。
- risk_analysis：风险分析结果表。
- risk_item：风险点明细表。
- ai_analysis_record：AI 分析记录表。
- ai_prompt_template：AI 提示词模板表。
- report_record：报告记录表。
- sys_config：系统参数表。
- sys_dict：系统字典表。
- operation_log：操作日志表。

## 10. AI 分析原型设计

### 10.1 输入内容

AI 分析服务输入建议包括：

- 制度标题。
- 制度类型。
- 发布部门。
- 适用范围。
- 制度正文。
- 分析目标。

### 10.2 输出结构

AI 输出建议采用结构化 JSON，方便后端保存和前端展示。

```json
{
  "summary": "制度摘要",
  "riskLevel": "HIGH",
  "riskScore": 82,
  "conflictExplanation": "疑似冲突说明",
  "riskItems": [
    {
      "title": "风险点标题",
      "description": "风险描述",
      "reason": "风险原因",
      "suggestion": "整改建议",
      "relatedClause": "相关条款"
    }
  ],
  "overallSuggestion": "总体整改建议"
}
```

### 10.3 MVP 风险等级

MVP 阶段先采用四级风险：

- LOW：低风险。
- MEDIUM：中风险。
- HIGH：高风险。
- CRITICAL：严重风险。

风险等级可先由 AI 建议生成，后续增量阶段再结合规则引擎和指标权重计算。

## 11. Sprint 计划

### Sprint 0：项目准备

目标：完成项目基础准备和全模块原型边界确认。

交付内容：

- 项目目录结构。
- 前后端基础工程。
- Gateway 原型工程或网关入口配置。
- 数据库连接配置。
- Redis 连接配置。
- 基础代码规范。
- 全模块原型页面草图。
- MVP 功能清单确认。

验收标准：

- 前端项目可启动。
- 后端项目可启动。
- 网关入口可访问后端健康检查接口。
- 数据库连接正常。
- Redis 连接正常。
- 能访问基础健康检查接口。

### Sprint 1：基础框架、用户权限与制度管理

目标：完成用户权限、菜单框架和制度录入闭环。

交付内容：

- 登录页。
- 基础认证接口。
- 用户列表、用户维护、角色分配。
- 菜单权限展示。
- 制度列表。
- 制度新增与编辑。
- 制度详情页。
- 用户、角色、菜单、制度相关数据库表。
- 操作日志基础记录。

验收标准：

- 用户可以登录系统。
- 管理员可以维护用户并分配角色。
- 不同角色可以看到不同菜单入口。
- 用户可以新增、编辑、查看制度。
- 制度数据可以持久化到 MySQL。
- 用户关键操作可以写入操作日志。

### Sprint 2：冲突检测、AI 服务与风险分析

目标：完成制度冲突检测、AI 分析服务和旗舰寻租风险分析闭环。

交付内容：

- AI 分析服务封装。
- 提示词模板配置。
- 冲突检测任务创建。
- 相似条款和规则字段简化检测。
- 冲突结果保存与确认。
- 发起旗舰寻租风险分析接口。
- 风险分析结果保存。
- 风险结果详情页。
- 分析中、成功、失败状态展示。
- AI 分析记录。
- 案例扩展分析原型。

验收标准：

- 用户可以选择制度发起冲突检测。
- 系统可以输出冲突结果并支持人工确认。
- 用户可以对一项制度发起旗舰寻租风险分析。
- 系统可以生成摘要、风险等级、风险点和整改建议。
- 分析结果可以保存并重新查看。
- AI 调用记录可以查询。

### Sprint 3：可视化、报告与系统基础设施

目标：完成可视化、报告预览和系统基础设施模块闭环。

交付内容：

- 工作台总览指标。
- 风险等级分布图。
- 制度类型分布图。
- 冲突状态分布图。
- 单项制度分析报告预览页。
- 报告数据聚合接口。
- 系统参数页面。
- 字典管理页面。
- 健康检查页面。
- 操作日志查询页面。
- 统一异常响应。

验收标准：

- 用户可以查看制度、冲突和风险统计。
- 图表可以根据真实数据展示。
- 用户可以打开单项制度分析报告预览。
- 管理员可以查看系统参数、字典、日志和健康状态。

### Sprint 4：全模块集成演示与修正

目标：完成七大模块端到端集成演示，并基于反馈修正 MVP。

交付内容：

- 页面交互优化。
- 用户权限边界修正。
- 冲突检测字段调整。
- 风险结果字段调整。
- AI 输出结构优化。
- 看板指标口径调整。
- 系统日志与异常处理补齐。
- 缺陷修复。

验收标准：

- MVP 可以完成七大模块端到端演示。
- 主要流程无阻断性缺陷。
- 已记录后续增量需求清单。

## 12. MVP 验收标准

MVP 总体验收标准如下：

- 用户与权限、制度管理、冲突检测、风险分析、AI 服务、可视化报告、系统基础设施七大模块均有可运行页面和接口。
- 登录、用户维护、制度录入、冲突检测、旗舰寻租风险分析、结果查看、看板展示、报告预览和系统管理流程完整可用。
- 核心数据可以保存到数据库。
- Redis 至少用于登录状态、缓存或限流中的一个原型场景。
- Spring Cloud Gateway 至少跑通统一入口路由和健康检查。
- AI 分析服务能够返回结构化结果，并被冲突检测、旗舰寻租风险分析或报告模块调用；未配置 LLM 时，寻租分析仍能通过本地规则完成闭环。
- 页面交互清晰，适合进行业务演示。
- 系统具备后续扩展精细权限、复杂冲突检测、风险规则引擎、报告导出和服务拆分的基础结构。

## 13. 后续增量路线

MVP 完成后，建议按以下顺序增量扩展：

1. 组织架构、数据权限和更细粒度的 RBAC 权限控制。
2. 制度版本管理、修订记录和版本比对。
3. 多制度批量冲突检测和语义冲突检测。
4. 旗舰寻租分析指标体系配置、权重管理和评分规则引擎。
5. 向量知识库、制度库检索和跨制度智能问答。
6. 报告导出、报告模板管理和报告审批流。
7. 审计日志增强、任务调度、监控告警和安全加固。
8. 网关能力增强、服务拆分、限流熔断和平台化部署。

## 14. 原型演示场景

MVP 演示建议使用以下场景：

1. 管理员登录系统。
2. 进入用户与权限管理，新增用户并分配角色。
3. 进入制度管理，新增两份制度并维护制度正文。
4. 进入制度冲突检测，选择两份制度发起检测并确认一条冲突结果。
5. 在制度详情页发起寻租风险分析，验证规则兜底或 LLM 增强结果。
6. 查看制度摘要、冲突说明、风险等级、风险点、判定原因和整改建议。
7. 进入风险看板，查看制度、冲突和风险统计图表。
8. 打开报告预览，查看单项制度分析报告。
9. 进入系统管理，查看系统参数、操作日志和健康检查状态。

该演示场景覆盖七大模块的最小运行闭环，可作为后续需求评审和项目汇报的基础。
