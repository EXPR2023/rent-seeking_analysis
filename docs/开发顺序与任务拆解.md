# 规章寻租行为分析平台开发顺序与任务拆解

## 1. 开发原则

项目采用“先基础、后业务；先闭环、后增强；先接口、后体验优化”的开发顺序。MVP 原型要求跑通全部七大模块，但开发优先级应围绕旗舰寻租风险分析展开：制度管理、冲突检测、AI 服务、看板报告和系统审计都要能支撑寻租分析结果的生成、解释、复核和展示。

开发优先级遵循：

1. 先搭建可运行环境。
2. 先完成数据库和公共后端能力。
3. 先完成登录、权限和菜单框架。
4. 再按业务数据流完成制度、冲突、旗舰寻租分析、AI、报告、系统管理。
5. 最后做全模块联调、演示数据和验收修正。

## 2. 总体开发路径

推荐分为 9 个阶段：

| 阶段 | 名称 | 目标 |
| --- | --- | --- |
| 阶段 0 | 环境与仓库准备 | 建立工程目录、Docker 基础设施和开发约定 |
| 阶段 1 | 数据库与初始化脚本 | 建立所有 MVP 表结构和基础数据 |
| 阶段 2 | 后端公共底座 | 完成统一响应、异常、安全、日志、配置 |
| 阶段 3 | 用户权限与菜单框架 | 跑通登录、用户、角色、菜单 |
| 阶段 4 | 制度管理模块 | 跑通制度录入、编辑、查询、详情 |
| 阶段 5 | 冲突检测与 AI 服务 | 跑通冲突任务、冲突项、AI 调用记录 |
| 阶段 6 | 旗舰寻租风险分析模块 | 跑通制度风险分析、风险项、复核 |
| 阶段 7 | 看板、报告与系统管理 | 跑通可视化、报告预览、参数、字典、健康检查 |
| 阶段 8 | 前后端全链路联调 | 完成七大模块演示闭环和缺陷修正 |

## 3. 阶段 0：环境与仓库准备

### 3.1 开发任务

- 创建项目根目录结构。
- 创建 `backend`、`gateway`、`frontend`、`database`、`docker` 目录。
- 编写 `.gitignore`。
- 编写 `.env.example`。
- 编写 Docker Compose 草案，包含 MySQL 和 Redis。
- 明确 JDK、Maven、Node.js、pnpm、Docker Desktop 版本。
- 确认本地端口：Gateway 8080、Backend 8081、Frontend 5173、MySQL 3306、Redis 6379。

### 3.2 交付物

- 项目基础目录。
- Docker Compose 基础配置。
- 环境变量示例文件。
- 可启动的 MySQL 和 Redis。

### 3.3 验收标准

- `docker compose up -d` 可正常启动 MySQL 和 Redis。
- MySQL、Redis 端口可连接。
- 项目目录与《开发环境搭建说明》一致。

## 4. 阶段 1：数据库与初始化脚本

### 4.1 开发任务

- 编写 `001_schema.sql`，创建全部 MVP 数据表。
- 编写 `002_seed_roles.sql`，初始化角色。
- 编写 `003_seed_dicts.sql`，初始化字典。
- 编写 `004_seed_configs.sql`，初始化系统参数。
- 编写 `005_seed_demo_data.sql`，初始化演示账号和真实监管制度样本。
- 为常用查询字段建立索引。

### 4.2 表结构范围

必须覆盖：

- `sys_user`
- `sys_role`
- `sys_user_role`
- `sys_menu`
- `regulation`
- `regulation_content`
- `conflict_detection_task`
- `conflict_item`
- `risk_analysis`
- `risk_item`
- `ai_prompt_template`
- `ai_analysis_record`
- `report_record`
- `sys_config`
- `sys_dict`
- `operation_log`

### 4.3 交付物

- 数据库建表脚本。
- 初始化数据脚本。
- 本地可用演示账号。

### 4.4 验收标准

- 空库执行初始化脚本无错误。
- 初始化后可以查询到角色、字典、系统参数和演示账号。
- 所有表字符集为 `utf8mb4`。

## 5. 阶段 2：后端公共底座

### 5.1 开发任务

- 创建 Spring Boot 后端工程。
- 建立 `common` 包结构。
- 实现统一响应 `ApiResponse`。
- 实现分页响应 `PageResponse`。
- 实现业务异常 `BizException`。
- 实现全局异常处理 `GlobalExceptionHandler`。
- 接入 MySQL。
- 接入 Redis。
- 接入 Spring Security。
- 实现 JWT 生成和解析。
- 实现操作日志切面基础能力。
- 创建健康检查接口。

### 5.2 交付物

- 可启动的 `backend` 工程。
- 公共返回结构。
- 公共异常处理。
- 数据库连接。
- Redis 连接。
- 基础安全配置。

### 5.3 验收标准

- `backend` 可在 `8081` 启动。
- `/api/system/health` 可返回后端、MySQL、Redis 状态。
- 未登录访问受保护接口返回 `UNAUTHORIZED`。
- 异常响应格式统一。

## 6. 阶段 3：用户权限与菜单框架

### 6.1 后端任务

- 实现登录接口 `/api/auth/login`。
- 实现退出接口 `/api/auth/logout`。
- 实现当前用户菜单接口 `/api/menus/current`。
- 实现用户列表、新增、编辑、启用、禁用。
- 实现角色列表。
- 实现用户角色分配。
- 写入登录和用户维护操作日志。

### 6.2 前端任务

- 创建 Vue 3 前端工程。
- 配置 Element Plus。
- 配置路由。
- 配置 Pinia 或等价状态管理。
- 配置统一 request。
- 实现登录页。
- 实现基础布局 `BasicLayout`。
- 实现侧边菜单。
- 实现用户列表页。
- 实现角色权限页。

### 6.3 交付物

- 可登录系统。
- 登录后可进入工作台。
- 可查看菜单。
- 可维护用户和角色分配。

### 6.4 验收标准

- 使用 `admin` 账号可登录。
- 登录后前端保存 Token。
- 刷新页面后仍可访问受保护页面。
- 不同角色可展示不同菜单入口。

## 7. 阶段 4：制度管理模块

### 7.1 后端任务

- 实现制度列表接口。
- 实现制度新增接口。
- 实现制度编辑接口。
- 实现制度详情接口。
- 实现制度逻辑删除接口。
- 实现制度正文保存。
- 维护制度分析状态字段。
- 写入制度维护操作日志。

### 7.2 前端任务

- 实现制度列表页面。
- 实现制度查询区。
- 实现制度新增和编辑表单。
- 实现制度详情页。
- 在详情页预留冲突检测、风险分析、报告预览入口。

## 8. 阶段 5：冲突检测与 AI 服务

### 8.1 冲突检测后端任务

- 实现冲突检测任务创建。
- 实现主制度和对比制度读取。
- 实现文本相似度简化检测。
- 实现适用范围、责任主体等字段比对。
- 写入 `conflict_detection_task`。
- 写入 `conflict_item`。
- 实现冲突任务列表和详情。
- 实现冲突项确认、忽略、备注。

### 8.2 AI 服务后端任务

- 接入 Spring AI。
- 实现提示词模板读取。
- 实现 AI 调用客户端。
- 实现 AI 分析记录保存。
- 实现 AI 失败降级。
- 实现案例扩展分析接口，支持围绕真实案例检索相关制度、抓取用户提供的官方链接、输出组织责任链和待导入材料。
- 保留单项制度问答接口作为兼容能力。
- 为冲突项生成简化冲突说明。

### 8.3 前端任务

- 实现冲突检测任务列表页。
- 实现创建冲突检测任务表单。
- 实现冲突检测详情页。
- 实现冲突确认和忽略操作。
- 实现 AI 分析记录页。
- 实现案例扩展分析页。

### 8.4 交付物

- 制度间冲突检测最小闭环。
- AI 调用记录可查询。
- 案例扩展分析可演示。

### 8.5 验收标准

- 选择两份制度可以创建冲突检测任务。
- 系统可以生成至少一类冲突结果。
- 用户可以确认或忽略冲突项。
- AI 调用成功或失败均有记录。

## 9. 阶段 6：旗舰寻租风险分析模块

### 9.1 后端任务

- 实现制度旗舰寻租风险分析接口。
- 读取制度正文和制度元数据。
- 优先执行本地规则兜底，识别自由裁量、审批集中、流程透明度不足、监督约束不足、利益关联和处罚弹性等风险。
- 配置 LLM 时调用 AI 服务增强摘要、风险项、风险等级、原因解释和整改建议。
- 使用固定规则或 LLM 建议生成风险分数。
- 写入 `risk_analysis`。
- 写入 `risk_item`。
- 更新制度分析状态。
- 实现风险详情接口。
- 实现风险复核接口。

### 9.2 前端任务

- 在制度详情页添加发起旗舰寻租风险分析按钮。
- 展示分析中、已完成、失败状态。
- 实现风险分析详情页。
- 展示风险等级、风险分数、风险点、原因、关联条款和建议。
- 实现复核备注。

### 9.3 交付物

- 单项制度旗舰寻租风险分析闭环。
- 风险结果可保存、查看、复核。

### 9.4 验收标准

- 用户可以对制度发起旗舰寻租风险分析。
- 系统可以保存风险分析主记录和风险项。
- 前端可以展示风险等级、风险点、判定原因、关联条款和整改建议。
- 用户可以填写复核备注。

## 10. 阶段 7：看板、报告与系统管理

- 前端实现报告预览页面。
- 保存报告记录或生成报告快照。

### 10.3 系统管理任务

- 实现系统参数列表和修改。
- 实现字典列表。
- 实现操作日志列表。
- 完善健康检查接口。
- 实现网关工程。
- 配置 `/api/**` 转发到 backend。

### 10.4 交付物

- 工作台看板。
- 报告预览。
- 系统参数。
- 字典管理。
- 操作日志。
- 健康检查。
- Gateway 统一入口。

### 10.5 验收标准

- 看板图表使用真实接口数据。
- 报告预览能展示制度、冲突、风险和建议。
- 系统参数可以修改并记录日志。
- 通过 `http://localhost:8080/api/system/health` 可以访问后端健康检查。

## 11. 阶段 8：前后端全链路联调

### 11.1 联调任务

- 统一接口路径和字段命名。
- 检查前端所有页面空态、加载态、错误态。
- 检查登录失效跳转。
- 检查权限菜单显示。
- 检查全模块操作日志。
- 准备演示数据。
- 编写验收测试清单。
- 修复阻断性缺陷。

### 11.2 必须跑通的演示流程

1. 管理员登录系统。
2. 新增用户并分配角色。
3. 新增两份制度并维护正文。
4. 发起制度冲突检测。
5. 确认或忽略冲突项。
6. 发起制度寻租风险分析。
7. 查看 AI 摘要、风险等级、风险点和整改建议。
8. 查看风险看板。
9. 打开制度报告预览。
10. 查看系统参数、操作日志和健康检查。

### 11.3 交付物

- 可演示的 MVP 原型。
- 全模块测试数据。
- 缺陷修复记录。
- 后续增量需求清单。

### 11.4 验收标准

- 七大模块均有可访问页面。
- 七大模块均有可调用接口。
- 七大模块均有数据库数据流转。
- 全链路演示无阻断性错误。
- 后续增强项已明确记录。

## 12. 任务依赖关系

| 前置任务 | 后续任务 |
| --- | --- |
| Docker、MySQL、Redis | 后端启动、数据库初始化 |
| 数据库表结构 | 所有业务接口 |
| 统一响应和异常处理 | 所有 Controller |
| 登录和 JWT | 前端路由守卫、业务接口鉴权 |
| 用户角色菜单 | 前端菜单和权限控制 |
| 制度管理 | 冲突检测、风险分析、报告预览 |
| AI 服务 | 冲突说明、旗舰寻租分析、案例扩展分析 |
| 冲突检测 | 看板、报告预览 |
| 风险分析 | 作为旗舰结果来源支撑看板、报告预览 |
| 系统参数和日志 | 系统管理演示、审计追踪 |

## 13. 优先级定义

| 优先级 | 含义 |
| --- | --- |
| P0 | MVP 演示必须完成，缺失会导致模块无法跑通 |
| P1 | MVP 建议完成，缺失不阻断主流程但影响完整度 |
| P2 | 后续增量增强，不进入当前 MVP 必做范围 |

## 14. P0 必做清单

P0 任务包括：

- Docker Compose 启动 MySQL 和 Redis。
- 初始化数据库表和演示数据。
- 后端统一响应、异常、JWT、安全配置。
- 登录、退出、当前菜单。
- 用户列表、角色分配。
- 制度列表、新增、编辑、详情。
- 冲突检测任务创建、冲突结果展示、冲突确认。
- AI 调用封装、AI 记录、AI 失败降级。
- 旗舰寻租风险分析发起、结果保存、详情展示。
- 看板总览、风险等级图、冲突状态图。
- 报告预览。
- 系统参数、操作日志、健康检查。
- Gateway 路由 `/api/**`。
- 前端基础布局、路由守卫、统一请求。

## 15. 建议开发节奏

建议以 2 周为一个 Sprint：

| Sprint | 内容 | 目标 |
| --- | --- | --- |
| Sprint 0 | 阶段 0 至阶段 2 | 环境、数据库、后端底座可用 |
| Sprint 1 | 阶段 3 至阶段 4 | 登录权限和制度管理可用 |
| Sprint 2 | 阶段 5 至阶段 6 | 冲突检测、AI 服务、旗舰寻租分析可用 |
| Sprint 3 | 阶段 7 | 看板、报告、系统管理、网关可用 |
| Sprint 4 | 阶段 8 | 全模块联调、演示和修正 |

## 16. 开发完成判定

当以下条件全部满足时，MVP 开发可视为完成：

- 使用一条启动说明可以启动 MySQL、Redis、backend、gateway、frontend。
- 管理员账号可以登录系统。
- 所有菜单均可访问。
- 制度可以新增、编辑、查看。
- 冲突检测可以生成结果。
- 旗舰寻租风险分析可以生成结果，并在无 LLM 环境下通过本地规则兜底。
- AI 调用有记录，失败可降级。
- 看板图表有真实数据。
- 报告预览可打开。
- 系统参数、日志、健康检查可查看。
- 演示流程连续执行无阻断。
