# 日常启动

本文档用于说明在不同设备上拉取代码后，如何快速跑通本地开发环境。

项目推荐的本地开发方式是：

- MySQL、Redis 使用 Docker Compose 启动。
- backend、gateway、frontend 在本机直接运行，方便调试和热更新。
- `.env` 每台设备单独维护，不提交到 Git。

## 一、新设备第一次配置

### 1. 拉取代码

可以把项目放在任意目录，后续命令都以项目根目录为准。

```powershell
git clone <仓库地址> rent-seeking_analysis
cd rent-seeking_analysis
```

如果已经有项目目录：

```powershell
cd <你的项目目录>
git pull
```

### 2. 安装基础软件

确认本机已经安装：

- Git
- Docker Desktop
- JDK 17 或 JDK 21
- Maven 3.9+
- Node.js LTS

检查命令：

```powershell
git --version
docker --version
docker compose version
java -version
mvn -version
node -v
npm -v
```

说明：

- 本仓库没有提交 `.tools/`，所以换设备后不要依赖旧电脑里的本地 Maven 目录。
- 如果你没有全局 Maven，也可以自己把 Maven 解压到 `.tools/`，但 `.tools/` 只作为本机工具目录，不提交。

### 3. 创建本机环境变量文件

```powershell
Copy-Item .env.example .env
```

然后按本机情况修改 `.env`。

重点检查：

```env
MYSQL_PORT=3307
REDIS_PORT=6379
BACKEND_PORT=8081
GATEWAY_PORT=8080
FRONTEND_PORT=5173
```

如果本机没有 MySQL 占用 3306，也可以把 `MYSQL_PORT` 改成 `3306`。但要保证 Docker Compose 和后端启动时读取的是同一个 `MYSQL_PORT`。

AI 相关密钥只写在本机 `.env` 里，不要提交：

```env
AI_ENABLED=true
AI_BASE_URL=
AI_API_KEY=
AI_MODEL=
```

### 4. 安装前端依赖

```powershell
cd frontend
npm install
cd ..
```

Java 依赖会在第一次运行 Maven 时自动下载。

## 二、每天启动项目

以下命令默认从项目根目录执行。

### 1. 启动 Docker 基础服务

```powershell
cd docker
docker compose --env-file ../.env up -d
docker compose ps
cd ..
```

正常情况下应看到 MySQL 和 Redis 都是 running 或 healthy。

### 2. 启动后端 backend

新开一个 PowerShell 终端，在项目根目录执行：

```powershell
Get-Content .env | ForEach-Object {
  if ($_ -and $_ -notmatch '^\s*#') {
    $name, $value = $_ -split '=', 2
    if ($name) {
      [Environment]::SetEnvironmentVariable($name.Trim(), $value, 'Process')
    }
  }
}

cd backend
mvn spring-boot:run "-Dspring-boot.run.profiles=local"
```

启动后验证：

```text
http://localhost:8081/api/system/health
```

### 3. 启动前端 frontend

再开一个 PowerShell 终端：

```powershell
cd frontend
npm run dev
```

访问：

```text
http://localhost:5173
```

当前前端开发服务器会把 `/api` 代理到 `http://localhost:8081`，所以日常本地开发只启动 backend 和 frontend 就能联调。

### 4. 可选：启动 gateway

如果需要测试网关路由，再开一个 PowerShell 终端：

```powershell
Get-Content .env | ForEach-Object {
  if ($_ -and $_ -notmatch '^\s*#') {
    $name, $value = $_ -split '=', 2
    if ($name) {
      [Environment]::SetEnvironmentVariable($name.Trim(), $value, 'Process')
    }
  }
}

cd gateway
mvn spring-boot:run "-Dspring-boot.run.profiles=local"
```

验证：

```text
http://localhost:8080/api/system/health
```

## 三、跨设备开发同步流程

### 从设备 A 切到设备 B 前

在设备 A 上：

```powershell
git status
git add .
git commit -m "描述本次修改"
git push
```

注意：

- `.env` 不会提交，需要每台设备自己维护。
- `node_modules/`、`target/`、`dist/`、`.tools/`、日志目录都不需要同步。
- Docker 数据卷是每台设备本地独立的，不会跟随 Git 同步。

### 在设备 B 上继续开发

```powershell
git pull
```

如果前端依赖有变化：

```powershell
cd frontend
npm install
cd ..
```

然后按“每天启动项目”的顺序启动即可。

## 四、数据库说明

第一次在某台设备上执行：

```powershell
cd docker
docker compose --env-file ../.env up -d
```

MySQL 容器会读取 `database/init` 下的初始化脚本。

如果初始化脚本变了，而本机已经创建过旧的数据卷，MySQL 不会自动重新执行初始化脚本。需要重建本机数据库时执行：

```powershell
cd docker
docker compose --env-file ../.env down -v
docker compose --env-file ../.env up -d
```

注意：`down -v` 会删除本机 Docker 数据卷，也就是清空本机数据库和 Redis 数据。

## 五、常见问题

### 1. 后端连不上 MySQL

先确认 `.env` 里的端口：

```powershell
Select-String -Path .env -Pattern '^MYSQL_PORT='
```

再确认 Docker 映射端口：

```powershell
cd docker
docker compose --env-file ../.env ps
```

后端、Docker Compose 必须使用同一个 `MYSQL_PORT`。

### 2. 端口被占用

检查端口占用：

```powershell
netstat -ano | findstr :3306
netstat -ano | findstr :3307
netstat -ano | findstr :6379
netstat -ano | findstr :8081
netstat -ano | findstr :5173
```

处理方式：

- 停掉占用端口的本机服务。
- 或修改 `.env` 中对应端口，再重启 Docker 和相关服务。

### 3. 前端页面能打开，但接口失败

检查：

- backend 是否已经启动。
- `http://localhost:8081/api/system/health` 是否正常。
- 前端终端里 Vite 代理是否报错。
- 浏览器控制台是否有接口错误。

### 4. 换设备后 Maven 命令不可用

安装 Maven 并配置 PATH，或把 Maven 解压到本机 `.tools/` 后使用完整路径启动，例如：

```powershell
.\.tools\apache-maven-3.9.9\bin\mvn.cmd -version
```

如果使用 `.tools` 里的 Maven，进入 backend 后启动命令可以写成：

```powershell
..\.tools\apache-maven-3.9.9\bin\mvn.cmd spring-boot:run "-Dspring-boot.run.profiles=local"
```
