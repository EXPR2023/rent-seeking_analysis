# 规章寻租行为分析平台开发环境搭建说明

## 1. 文档目的

本文档用于规范规章寻租行为分析平台 MVP 原型阶段的本地开发环境。项目推荐采用“本机开发 + Docker Compose 托管基础设施”的混合式容器化开发方式。

该方式将后端 Spring Boot、前端 Vue 3 放在本机 IDE 中运行，便于调试和热更新；将 MySQL、Redis 等基础设施放入 Docker 容器，保证环境一致、启动简单、便于重建。

## 2. 推荐开发模式

### 2.1 总体方案

| 组件 | 推荐运行方式 | 说明 |
| --- | --- | --- |
| 后端业务服务 backend | 本机运行 | 使用 IntelliJ IDEA 调试 Spring Boot |
| 网关服务 gateway | 本机运行，后续可容器化 | MVP 阶段便于联调和观察路由 |
| 前端 frontend | 本机运行 | 使用 VS Code 或 WebStorm，支持热更新 |
| MySQL | Docker Compose | 保证数据库版本和初始化数据一致 |
| Redis | Docker Compose | 用于缓存、会话、限流或任务状态 |
| AI 服务 | 远程模型优先 | 通过配置接入 Spring AI，后续可接本地模型 |
| 数据库脚本 | 本地目录挂载 | 初始化表结构和基础数据 |

### 2.2 不推荐纯虚拟机开发

纯虚拟机开发环境启动慢、资源占用高、维护成本大，不适合作为 MVP 快速迭代阶段的默认方案。

### 2.3 不推荐一开始全容器开发

前后端业务代码完全运行在容器中会增加断点调试、热更新、依赖安装和日志观察成本。MVP 阶段优先保证开发效率，因此业务服务本机运行更合适。

## 3. 基础软件要求

### 3.1 操作系统

推荐环境：

- Windows 10/11。
- Docker Desktop + WSL2。
- PowerShell 7 或 Windows PowerShell。

也可使用 macOS 或 Linux，命令需要按系统略作调整。

### 3.2 必装软件

| 软件 | 推荐版本 | 用途 |
| --- | --- | --- |
| Git | 2.40+ | 代码版本管理 |
| JDK | 21 LTS，或 17 LTS | Spring Boot 开发 |
| Maven | 3.9+ | Java 依赖管理和构建 |
| Node.js | 当前 LTS | Vue 3 前端开发 |
| pnpm | 9+ | 前端包管理 |
| Docker Desktop | 最新稳定版 | 容器运行环境 |
| MySQL Client | 8.0+ | 数据库连接与调试 |
| Redis CLI | 7+，可选 | Redis 调试 |
| IntelliJ IDEA | 2024+ | 后端开发 |
| VS Code 或 WebStorm | 最新稳定版 | 前端开发 |

### 3.3 推荐端口

| 服务 | 端口 |
| --- | --- |
| Gateway | 8080 |
| Backend | 8081 |
| Frontend | 5173 |
| MySQL | 3306 |
| Redis | 6379 |

如本机端口冲突，可在本地配置文件中调整，但团队默认端口应保持一致。

## 5. Docker Compose 环境规划

### 5.1 容器服务

MVP 阶段 Docker Compose 至少包含：

- MySQL 8。
- Redis 7。

后续可扩展：

- Adminer 或 phpMyAdmin。
- RedisInsight。
- 本地大模型服务。
- 后端和网关容器镜像。

### 5.2 MySQL 配置建议

| 配置项 | 建议值 |
| --- | --- |
| 数据库名 | rent_seeking_analysis |
| 字符集 | utf8mb4 |
| 排序规则 | utf8mb4_0900_ai_ci |
| 时区 | Asia/Shanghai 或 Asia/Singapore |
| root 密码 | 仅本地使用，写入 `.env` |
| 应用账号 | rent_app |

数据库连接示例：

```text
jdbc:mysql://localhost:3306/rent_seeking_analysis?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Singapore
```

### 5.3 Redis 配置建议

| 配置项 | 建议值 |
| --- | --- |
| Host | localhost |
| Port | 6379 |
| Database | 0 |
| Password | MVP 本地可为空，团队环境建议设置 |

Redis Key 前缀遵循设计规格说明：

```text
auth:token:{tokenId}
dashboard:summary
ai:task:{taskId}:status
rate:api:{userId}:{path}
```

## 6. 环境变量规范

项目根目录后续应提供 `.env.example`，开发者复制为 `.env` 后本地修改。

建议变量：

```env
MYSQL_DATABASE=rent_seeking_analysis
MYSQL_ROOT_PASSWORD=local_root_password
MYSQL_USER=rent_app
MYSQL_PASSWORD=rent_app_password

REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_PASSWORD=

BACKEND_PORT=8081
GATEWAY_PORT=8080
FRONTEND_PORT=5173

AI_ENABLED=true
AI_PROVIDER=openai-compatible
AI_BASE_URL=
AI_API_KEY=
AI_MODEL=
```

`.env` 不应提交到 Git，仅提交 `.env.example`。

## 10. 推荐启动顺序

开发联调时建议按以下顺序启动：

1. 启动 Docker Desktop。
2. 启动 MySQL 和 Redis。
3. 执行或确认数据库初始化脚本。
4. 启动 backend。
5. 启动 gateway。
6. 启动 frontend。
7. 通过前端访问并联调接口。

基础设施启动示例：

```powershell
cd docker
docker compose up -d
```

查看容器状态：

```powershell
docker compose ps
```

停止容器：

```powershell
docker compose down
```

重建容器：

```powershell
docker compose up -d --build
```

## 14. 常见问题

### 14.1 MySQL 端口被占用

检查端口：

```powershell
netstat -ano | findstr :3306
```

处理方式：

- 停止本机已有 MySQL。
- 或将 Docker Compose 中 MySQL 映射端口改为 `3307:3306`。

### 14.2 Redis 端口被占用

检查端口：

```powershell
netstat -ano | findstr :6379
```

处理方式：

- 停止本机 Redis。
- 或将 Redis 映射端口改为 `6380:6379`。

### 14.3 前端无法访问接口

检查：

- Gateway 是否启动。
- `VITE_API_BASE_URL` 是否指向 `http://localhost:8080/api`。
- Gateway 是否正确转发 `/api/**`。
- 后端健康检查是否正常。
- 浏览器控制台是否存在 CORS 错误。

### 14.4 AI 服务不可用

寻租风险分析是项目旗舰功能，MVP 阶段必须支持 AI 降级，保证无 LLM 环境下仍可演示：

- `AI_ENABLED=false` 或未配置模型参数时，使用本地规则生成风险等级、风险项和整改建议。
- AI 调用失败时保存失败记录，并自动回退到本地规则结果，不阻断寻租分析主链路。
- 前端展示分析结果和复核入口，并允许重新分析。

## 15. 环境验收清单

开发环境搭建完成后，应满足以下条件：

- `docker compose ps` 可看到 MySQL、Redis 正常运行。
- MySQL 中存在 `rent_seeking_analysis` 数据库。
- Redis 可正常连接。
- backend 可启动并访问 `/api/system/health`。
- gateway 可启动并转发 `/api/system/health`。
- frontend 可启动并访问登录页。
- 前端可通过 gateway 调用登录接口。
- 能使用管理员账号进入系统。
- 能看到用户权限、制度管理、冲突检测、旗舰寻租风险分析、AI 服务、可视化报告、系统基础设施等菜单入口。

## 16. 后续演进

MVP 稳定后，可逐步演进为更完整的开发环境：

- 增加 Dev Container，统一团队开发环境。
- 将 backend、gateway 打包为 Docker 镜像。
- 增加 Nginx 前端容器。
- 引入 Flyway 或 Liquibase 管理数据库迁移。
- 增加 CI/CD 流水线。
- 增加测试数据库和集成测试环境。
- 增加生产环境 Docker Compose 或 Kubernetes 部署方案。
