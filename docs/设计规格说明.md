# 规章寻租行为分析平台设计规格说明

## 1. 文档目的

本文档基于《MVP原型开发文档》，为规章寻租行为分析平台的原型开发提供代码级设计规范。内容覆盖程序规格说明和数据规格说明，作为后续创建前后端工程、数据库脚本、接口联调和测试用例的基础依据。

MVP 原型必须跑通以下七大模块：

- 用户与权限管理模块。
- 规章制度管理模块。
- 制度冲突检测模块。
- 寻租风险分析模块。
- AI 分析服务模块。
- 可视化与报告模块。
- 系统基础设施模块。

其中，寻租风险分析模块是项目旗舰功能。其他模块应围绕该主链路提供支撑：制度管理提供文本与元数据，冲突检测提供制度缺陷线索，AI 分析服务增强摘要与归因，看板和报告沉淀分析结果。

## 2. 总体技术架构

### 2.1 工程形态

MVP 阶段采用前后端分离架构。

```text
rent-seeking-analysis
├── backend                 # Spring Boot 业务服务
├── gateway                 # Spring Cloud Gateway 网关服务
├── frontend                # Vue 3 前端应用
├── database                # 数据库脚本
└── docs                    # 项目文档
```

MVP 后端业务服务先采用单体模块化结构，避免过早拆分微服务。网关服务保留独立工程，用于跑通统一入口、路由转发和健康检查。

### 2.2 技术选型

| 层级 | 技术 | 用途 |
| --- | --- | --- |
| 网关 | Spring Cloud Gateway | 统一入口、路由、跨域、限流预留 |
| 后端 | Spring Boot | 核心业务服务 |
| 安全 | Spring Security | 登录认证、接口鉴权 |
| AI | Spring AI | 大模型调用封装 |
| 数据库 | MySQL | 业务数据持久化 |
| 缓存 | Redis | 登录状态、缓存、限流计数 |
| 前端 | Vue 3 | 前端应用 |
| UI | Element Plus | 后台管理界面组件 |
| 图表 | ECharts | 可视化统计图表 |

### 3.2 分层规范

每个业务模块统一采用以下分层：

| 层级 | 命名后缀 | 职责 |
| --- | --- | --- |
| Controller | `*Controller` | 接收 HTTP 请求、参数校验、返回统一响应 |
| Service | `*Service` | 定义业务接口 |
| ServiceImpl | `*ServiceImpl` | 实现业务逻辑、事务控制 |
| Mapper/Repository | `*Mapper` 或 `*Repository` | 数据访问 |
| Entity | `*Entity` | 数据库表映射 |
| DTO | `*Request`、`*Response` | 接口入参与出参 |
| Converter | `*Converter` | Entity、DTO、VO 转换 |

Controller 不直接访问 Mapper。跨模块调用优先调用对方 Service，不直接操作对方数据表。

### 3.3 命名规范

- Java 类名使用 PascalCase，例如 `RegulationController`。
- Java 方法和变量使用 camelCase，例如 `createRegulation`。
- 数据库表名使用小写下划线，例如 `risk_analysis`。
- 数据库字段名使用小写下划线，例如 `created_at`。
- REST 接口路径使用小写复数名词，例如 `/api/regulations`。
- 枚举值使用大写下划线，例如 `IN_PROGRESS`。

### 3.4 统一响应结构

所有后端接口统一返回：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {},
  "traceId": "20260528203000123"
}
```

Java 类型建议：

```java
public class ApiResponse<T> {
    private String code;
    private String message;
    private T data;
    private String traceId;
}
```

分页响应结构：

```json
{
  "records": [],
  "pageNo": 1,
  "pageSize": 10,
  "total": 100
}
```

Java 类型建议：

```java
public class PageResponse<T> {
    private List<T> records;
    private Integer pageNo;
    private Integer pageSize;
    private Long total;
}
```

### 3.6 统一异常处理

后端必须提供 `GlobalExceptionHandler`，统一处理：

- 参数校验异常。
- 认证授权异常。
- 业务异常。
- 数据不存在异常。
- AI 服务调用异常。
- 未知系统异常。

业务异常统一使用：

```java
public class BizException extends RuntimeException {
    private final String code;
}
```

### 3.7 安全规范

MVP 阶段采用 Spring Security + JWT。

JWT 内容至少包含：

- userId。
- username。
- roleCodes。
- expireTime。

接口权限约定：

| 接口类型 | 权限要求 |
| --- | --- |
| `/api/auth/**` | 放行登录 |
| `/api/dashboard/**` | 登录用户 |
| `/api/regulations/**` | 制度管理员、分析人员、只读用户按操作区分 |
| `/api/conflict-*/**` | 制度管理员、分析人员 |
| `/api/risk-*/**` | 制度管理员、分析人员 |
| `/api/system/**` | 系统管理员 |
| `/api/audit/**` | 系统管理员 |

MVP 阶段权限可先基于角色编码判断，后续扩展为菜单、按钮、接口三层权限。

### 3.8 审计日志规范

以下操作必须记录操作日志：

- 登录、退出。
- 新增、编辑、删除制度。
- 发起冲突检测。
- 确认或忽略冲突项。
- 发起旗舰寻租风险分析。
- 修改风险复核备注。
- 修改系统参数。
- 用户新增、禁用、角色分配。

日志记录字段见 `operation_log` 表。

### 3.9 Redis 使用规范

MVP 至少实现一个 Redis 场景，推荐：

- 登录 Token 黑名单或会话状态。
- 看板统计缓存。
- AI 分析任务状态缓存。

Key 命名规范：

```text
auth:token:{tokenId}
dashboard:summary
ai:task:{taskId}:status
rate:api:{userId}:{path}
```

#### 4.3.3 检测规则

MVP 采用三类简化规则：

| 规则 | 说明 | 输出 |
| --- | --- | --- |
| TEXT_SIMILARITY | 条款文本相似度检测 | 疑似重复或表达冲突 |
| SCOPE_CONFLICT | 适用范围字段比对 | 适用范围不一致 |
| SUBJECT_CONFLICT | 责任主体字段比对 | 权责主体不一致 |

文本相似度 MVP 可先使用分词后的 Jaccard 相似度或简单字符串相似度。相似度大于等于 0.75 时标记为疑似冲突。

| --- | --- |
| DUPLICATE | 重复 |
| INCONSISTENT | 不一致 |

| SUBJECT_CONFLICT | 主体冲突 |
| TIME_CONFLICT | 时间冲突 |

| 枚举 | 说明 |
| --- | --- |
| LOW | 低 |
| MEDIUM | 中 |

### 4.4 寻租风险分析模块

寻租风险分析是系统的核心业务能力。MVP 必须同时具备本地规则兜底和 LLM 增强两层实现：未配置 LLM 时仍可根据固定指标输出风险项、风险等级和建议；配置 LLM 后，优先使用模型返回的结构化摘要、风险项、评分和整改建议，并保留人工复核状态。

#### 4.4.1 后端类

```text
RiskAnalysisController
RiskAnalysisService
RiskRuleService
RiskScoreService
RiskItemConverter
```

#### 4.4.2 核心接口

| 接口 | 方法 | 入参 | 出参 |
| --- | --- | --- | --- |
| `/api/regulations/{id}/analyze` | POST | `RiskAnalyzeRequest` | `Long` |
| `/api/risk-analyses/{id}` | GET | path id | `RiskAnalysisDetailResponse` |
| `/api/risk-analyses/{id}/review` | PUT | `RiskReviewRequest` | `Boolean` |

#### 4.4.3 MVP 风险指标

| 指标编码 | 指标名称 | 说明 |
| --- | --- | --- |
| DISCRETIONARY_POWER | 自由裁量权 | 是否存在宽泛、模糊、可自由解释条款 |
| APPROVAL_CONCENTRATION | 审批集中度 | 是否集中于单一部门或个人 |
| PROCESS_TRANSPARENCY | 流程透明度 | 是否缺少公开流程、时限、标准 |
| SUPERVISION_CONSTRAINT | 监督约束 | 是否缺少复核、监督、问责机制 |
| BENEFIT_RELATED | 利益关联 | 是否涉及资源分配、资格认定、资金补贴等 |
| PENALTY_FLEXIBILITY | 处罚弹性 | 是否处罚标准弹性过大 |

MVP 本地规则应覆盖以上指标。规则命中结果需要保存为 `risk_item`，并在报告和看板中作为旗舰分析结果展示；LLM 结果应映射到相同指标编码，避免前端和报告出现两套口径。

#### 4.4.4 风险状态

| 枚举 | 说明 |
| --- | --- |
| NOT_ANALYZED | 未分析 |
| ANALYZING | 分析中 |
| COMPLETED | 已完成 |
| FAILED | 分析失败 |

风险复核状态：

| 枚举 | 说明 |
| --- | --- |
| PENDING | 待复核 |
| CONFIRMED | 已确认 |
| ADJUSTED | 已调整 |

#### 4.5.3 AI 输出结构

AI 服务返回内容必须尽量约束为 JSON。`RENT_SEEKING_RISK` 是旗舰场景，返回结构应优先满足风险分析详情页、报告预览和复核流程使用：

```json
{
  "summary": "制度摘要",
  "riskLevel": "HIGH",
  "riskScore": 82,
  "conflictExplanation": "疑似冲突说明",
  "riskItems": [
    {
      "title": "风险点标题",
      "description": "风险描述",
      "reason": "风险原因",
      "suggestion": "整改建议",
      "relatedClause": "相关条款"
    }
  ],
  "overallSuggestion": "总体整改建议"
}
```

后端必须对 AI 返回进行 JSON 解析校验。解析失败时，应记录原始返回内容，并返回 `AI_SERVICE_ERROR` 或降级为本地规则分析结果，确保旗舰寻租分析链路不中断。

- 后台页面使用 `BasicLayout`。
- 列表页统一包含查询区、操作区、表格区、分页区。
- 新增和编辑优先使用抽屉或弹窗。
- 详情页优先使用 `el-descriptions`、`el-tabs` 和时间线展示。
- 风险等级使用不同颜色 Tag。
- 看板图表使用 ECharts，图表数据必须来自接口。

## 9. 开发约束

### 9.1 事务边界

以下方法必须加事务：

- 新增或编辑制度及正文。
- 创建冲突检测任务并写入冲突项。
- 发起旗舰寻租风险分析并写入风险结果。
- 用户角色分配。
- 修改系统参数并写入操作日志。

### 9.2 参数校验

Controller 入参必须使用 Bean Validation：

- 必填字段使用 `@NotBlank`、`@NotNull`。
- 字符长度使用 `@Size`。
- 分页参数限制 `pageSize` 最大值为 100。
- ID 必须为正数。

### 9.3 删除规范

业务数据默认逻辑删除。以下表不允许物理删除：

- regulation。
- risk_analysis。
- conflict_detection_task。
- ai_analysis_record。
- operation_log。

### 9.4 测试要求

MVP 阶段至少覆盖：

- 登录接口测试。
- 制度新增、编辑、查询测试。
- 冲突检测任务创建测试。
- 旗舰寻租风险分析结果保存测试。
- 看板统计接口测试。
- 系统健康检查测试。

## 10. 开发顺序建议

建议按以下顺序落地代码：

1. 创建后端、网关、前端、数据库目录。
2. 完成数据库初始化脚本。
3. 完成后端 common、认证、安全、统一响应和异常处理。
4. 完成用户、角色、菜单模块。
5. 完成制度管理模块。
6. 完成冲突检测模块。
7. 完成 AI 分析服务模块。
8. 完成旗舰寻租风险分析模块。
9. 完成看板和报告模块。
10. 完成系统参数、字典、操作日志和健康检查。
11. 完成前端页面和接口联调。
12. 完成全模块演示数据和验收测试。
